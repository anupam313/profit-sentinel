  not a prerequisite for D1 to fire

### CSV Upload Flow — Complete Spec

**File validation (in order):**
1. Format check: CSV and .xlsx only. Reject PDFs, images. Specific message.
2. Minimum column detection: ≥1 SKU-like column + ≥1 cost-like column.
   Reject with specific message if not found.
3. Currency question at upload: "Are all costs in this file in USD?"
   - Yes → proceed
   - No → ask which currencies present → ask founder-stated exchange
     rate per currency → convert to USD at upload using stated rate →
     store original_currency and fx_rate_used in sku_cost_master
   - If currency column exists in file → use per row
   - Blank currency rows → flag as unprocessable, write rest,
     surface blanks in reconciliation output file
   - Multiple currencies in cost column with no currency column →
     reject file: "Please add a currency column before re-uploading"
   - NEVER use live FX rates — historical COGS locked at PO rate
4. Landed vs ex-factory: ask once per file → if ex-factory apply multiplier
   → founder confirms multiplier value
5. Zero or negative cost values → flag, do not write to sku_cost_master
6. Duplicate SKU within single file with different costs → flag both,
   ask founder which to use, never auto-resolve
7. Version conflict: SKU exists in previous file, new file has different
   cost → surface conflict, ask founder to confirm update, never
   silently overwrite

**SKU matching:**
- Normalise both sides: lowercase, strip special characters,
  strip common prefixes/suffixes
- Exact match → write silently to sku_cost_master
- Fuzzy match → reconciliation output file only, never auto-write
- No match → reconciliation output file, flag as needs cost

**Reconciliation output file columns:**
| Shopify SKU | Shopify Product Name | Match Found | Matched CSV SKU |
Confidence | Unit Cost | Currency | Landed/Ex-factory | Action Needed |

- Sent to COGS owner immediately after upload — not during onboarding
- Founder sees: "We've sent [X] SKUs to [email] for review"
- Founder not burdened with 100+ row review during onboarding

**Multiple file handling:**
- Unlimited uploads accepted
- SKU-level mapping across all files, latest upload wins on conflict
- Historical inactive SKUs retained with active = false
- When inactive SKU goes live again → surface: "We have cost data for
  this SKU from a previous file — is it still accurate?"

### COGS Owner Flow

**At onboarding:**
- After fuzzy/unmatched SKUs detected: "We found [X] SKUs we couldn't
  confidently match. Who should we send these to for offline review? [email]"

- Send reconciliation file to COGS owner immediately
- Reconciliation output also useful internally for COGS owner's own records

**Ongoing gap alerts:**
- Always CC founder — never route exclusively to COGS owner
- Responsiveness tracked: second consecutive miss → escalation
  to founder accelerated to Day 5

**Escalation cadence (US business days only, US federal holiday calendar
hardcoded — no question asked):**
- Day 0: Alert to COGS owner
- Day 5: Reminder to COGS owner
- Day 10: Escalation to founder — COGS owner hasn't responded
- Day 15: Single reminder to founder
- Day 20: Final notice to founder with two buttons:
  → "Don't remind me about missing costs"
     Suppresses existing SKU reminders, logs cogs_gap_suppressed = true,
     new SKUs still trigger fresh cycle
  → "Update COGS contact"
     Replaces owner email, restarts cycle from Day 0
- After Day 20: Hard stop on reminders

**Post opt-out:**

- Never mentioned again unless new SKUs trigger fresh cycle
