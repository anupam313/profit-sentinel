## Schema Changes to Note for Future Sessions

### Sentry — sentry_errors_daily does not exist

The originally planned table name `sentry_errors_daily` was never
created. The real Airbyte Sentry connector produced three tables:

  sentry_events    (34 cols)
  sentry_issues    (36 cols)
  sentry_projects  (31 cols)

Every future reference to sentry_errors_daily must be replaced with
these three tables. This affects:
  - technical_architecture.md Section 3.3 and Section 5 (dbt models)
  - Step 5 seed script: seed sentry_events and sentry_issues
    (sentry_projects is config data, not time-series; seed separately)
  - Step 6 dbt models: stg_sentry_errors_daily.sql → write as
    stg_sentry_issues.sql and stg_sentry_events.sql
  - Agent A signal library: sentry error rate signals read from
    sentry_issues, not a daily roll-up table

### Loop Returns — schema corrected from placeholder

Both tables were dropped and rebuilt from the official API docs.
All references in dbt models and agent logic must use the corrected
field names.

  loop_returns — 13 → 47 columns. Key field name changes:
    id             text     (was bigint)
    state          text     (was status)
    type           text     (was return_type)
    customer       text     (was customer_id bigint)
    destination_id text     (was destination)
    order_id       text     (was bigint)
    processed_at   REMOVED  (never existed in API)
    total_refund_amount REMOVED → replaced by return_product_total,
      return_tax_total, return_total, return_credit_total,
      exchange_total, refund (and 6 more financial fields)

  loop_return_line_items — 13 → 27 columns. Key changes:
    line_item_id   text     (was id bigint)
    return_id      text     (FK added — was absent)
    provider_line_item_id   (was order_line_item_id)
    price/discount/tax text (were numeric)
    quantity       REMOVED  (never existed in API)
    return_reason_detail REMOVED → return_comment

  loop_refunds — DROPPED
    No API endpoint for separate refund records exists in Loop Returns.
    Refund data lives in:
      loop_returns.refund              (total refund amount)
      loop_return_line_items.refund    (per-line amount)
      loop_return_line_items.refund_item
      loop_return_line_items.refund_tax
    Do not recreate this table. Do not reference it in dbt or agents.
