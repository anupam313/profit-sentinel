## D1 GAP 2 — THRESHOLD DEFINITION — FULLY LOCKED

### Core Principle

---

### TRIGGER A — Step Change Detection

**Unit of analysis:** Rolling 7-day CM window. All 7 days must be clean
(no event, echo, or exclusion flag). Must contain ≥1 Saturday AND ≥1 Sunday.
If a full clean 7-day window with weekend representation cannot be formed →
Trigger A does not fire that week.

**Baseline:** Brand-specific IQR band (p25–p75) derived from verified BAU days.

```
structural_cm_baseline = IQR(p25, p75) of daily_cm
    WHERE day passes ALL exclusion filters:
        - brand_event_calendar: no active event
        - echo_period_active: not active
        - collection_launch_suppression: not active
        - influencer_campaign_active: not active
        - peak_suppression: not active
    AND day is in trailing 90 days (not 180 — seasonal contamination risk)
    AND minimum 20 qualifying BAU days available
```

Baseline recalculated weekly. Stored in client_config with
`structural_cm_baseline_updated_at` and `structural_cm_bau_day_count`.

**D1 Trigger A fires when:**
```
current_7day_cm < p25(BAU CM days) − threshold
AND no exclusion flag active
AND full clean 7-day window with ≥1 Saturday + ≥1 Sunday
AND minimum 20 BAU days in baseline
AND structural_break_detected = false
AND Trigger A not already fired this week
```

**Adaptive threshold:**
```
threshold = MIN(MAX(bau_cm_daily_sd × 2.0, 3pp floor), 8pp ceiling)
```
- SD = standard deviation of daily CM across all BAU days in baseline
- 3pp floor: prevents threshold being trivially small for very stable brands
- 8pp ceiling: prevents volatile brands waiting for catastrophic drops

**Urgency tier:** HIGH (🟠)

### ECHO PERIOD — LOCKED

Three states a day can be in:
- **State 1 — Active event:** Sale, influencer campaign, collection launch active.
  D1 suppressed. Day excluded from BAU baseline.
- **State 2 — Echo period:** Event ended but return volume still elevated.
  D1 suppressed. Day excluded from BAU baseline.
- **State 3 — BAU:** No active event, echo not active, returns within normal range.
  Day qualifies for baseline construction and for D1 to fire.

**Echo period opens when:**
```
flagged event ended within last N days (N = event-type cap below)
AND daily_return_count ≥ 1.5× structural_bau_return_rate
```

**Echo period closes when:**
```
rolling_7day_return_rate < 1.3× BAU return rate
for 7 consecutive days
OR event-type cap elapsed (whichever comes first)
```

Hysteresis: opens at 1.5×, closes at 1.3× — prevents oscillation.

**Event-type caps (maximum duration — data-driven close can happen earlier):**
| Event type | Cap |
|------------|-----|
| Standard (flash sale, influencer campaign, collection launch) | Brand's configured return_window_days (default 21 days) |
| Peak (BFCM, Boxing Day — flagged peak=true in brand_event_calendar) | return_window_days × 1.5, capped at 45 days |

**New column required:** `echo_period_active` boolean in `brand_event_calendar`.

Onboarding question is insufficient — pivots and business changes happen
continuously. Continuous detection replaces one-time question.

**30-day rolling self-detection:**
```
Every 30 days, compare:
    recent_p50 (last 30 BAU days) vs prior_p50 (prior 60 BAU days)

IF ABS(recent_p50 − prior_p50) > 5pp
AND recent_p25 and recent_p75 are both above or both below prior band
AND shift has persisted ≥21 BAU days
→ structural_break_detected = true
→ baseline reset: use only BAU days post-break
→ founder message: "Your margin profile appears to have shifted
  structurally. We've recalibrated your baseline. Was there a
  business change around [date]?"
```

Founder question is retrospective confirmation of what data already
detected — not a prospective gate.

Onboarding question retained as a lightweight historical data quality
filter only. Continuous detection handles everything forward.

### SELF-CALIBRATING BAU BOOTSTRAP — LOCKED

Prevents circular dependency between exclusion filters and baseline.

```
Pass 1: Exclude only hard event calendar flags.
         Compute rough BAU return rate from remaining days.
Pass 2: Apply echo period filter using rough BAU return rate.
         Recompute BAU return rate from refined set.
Pass 3: One more iteration to stabilise.
         Compute season profile from refined BAU set.
```

Three passes is sufficient for convergence.

**BAU coverage audit:**
```
bau_coverage_rate = bau_days / total_days_in_window
```

If `bau_coverage_rate < 15%` after 3-pass bootstrap:
→ Diagnose which filter is responsible (>60% exclusions from one filter
  = filter likely over-broad; evenly distributed = genuinely event-dense)
→ If genuinely event-dense: set `sparse_bau_profile = true`

**Sparse BAU profile brands (permanently promotional):**
- D1 Trigger A: DISABLED
- D1 Trigger B: DISABLED
- D2 (Discount Dependency Creep) elevated to primary margin health signal
- `sparse_bau_profile = true` stored in client_config
- No founder-facing message about disabled alerts
- CS flag for customer success team

### TRIGGER B — SLOW BLEED DETECTION — LOCKED

**Core insight:** Slow bleed is only visible when comparing BAU to BAU —
stripping out all event and echo contamination and asking whether clean
operating margin is drifting downward over successive clean periods.

**Unit of analysis:** Complete BAU week — all 7 days clean, no exclusion
flags, no public holidays falling within the week.

**Why complete weeks:** Eliminates day-mix contamination entirely. A
complete week always has exactly 1 Saturday, 1 Sunday, and 5 weekdays.
No normalisation needed. No z-scores. No day-type medians.

**Minimum:** 8 complete same-season BAU weeks.

**Trigger B disabled when:**
- `sparse_bau_profile = true` (no clusters form)
- Available history < 12 months (cannot detect seasonality reliably)
- `seasonal_profile = 'undetected'`
Internal log only: `trigger_b_disabled_reason`. No founder-facing message.

### SEASON DETECTION — LOCKED

Season derived from the brand's own BAU order volume, not from a fixed calendar.

```
brand_season_profile derived from:
    rolling_28day_median(daily_order_count)
    on BAU days only (after 3-pass bootstrap)
    across all available history (minimum 12 months)

Local peaks = high season windows
Local troughs = low season windows
Transition = slope-change periods between peak and trough
```

**Flat profile detection (no meaningful seasonality):**
```
seasonal_signal_strength =
    (rolling_28day_peak_order_count − rolling_28day_trough_order_count)
    / SD(daily_bau_order_count)

IF seasonal_signal_strength < 2.0:
    seasonal_profile = 'flat'
    # All complete BAU weeks comparable regardless of calendar position
ELSE:
    seasonal_profile = 'seasonal'
```

Threshold of 2.0 is consistent with the 2SD framework applied throughout.

**Cross-season year-on-year comparison:**
Enabled when:
- No structural_break_detected between the two periods
- Minimum 3 complete same-season BAU weeks in each year's equivalent window
- Available history ≥ 13 months

### MANN-KENDALL + THEIL-SEN DETECTION — LOCKED

**Why not linear regression:** Fashion DTC margin is non-linear. Linear
regression assumes linearity and is unreliable at N=8–20. Outlier weeks
dominate slope estimates.

**Why Mann-Kendall:** Non-parametric. No linearity assumption. Works
reliably at N=8–20. Detects monotonic decline whether linear, accelerating,
or step-change. Robust to outlier weeks.

**Why Theil-Sen:** Natural companion to Mann-Kendall. Median of all
pairwise slopes — robust to outliers. Expressed in interpretable units
(pp per week). Does not assume linearity.

**Firing condition:**
```
Trigger B fires when ALL of the following:

1. Minimum 8 complete same-season BAU weeks available
2. Mann-Kendall test: significant downward trend (p < 0.10)
3. Theil-Sen slope < −magnitude_threshold
4. No structural_break_detected in window
5. Trigger A not firing this week
6. seasonal_profile detected (≥12 months history, not 'undetected')
```

**Magnitude threshold (brand-adaptive, no hardcoding):**
```
bau_weekly_cm_sd = SD of complete BAU weekly CM values
                   across same window used for Mann-Kendall

magnitude_threshold = MIN(MAX(bau_weekly_cm_sd × 0.20, 0.2pp floor), 0.5pp ceiling)
```
- 0.20 × SD: brand loses 20% of one SD of natural CM volatility per week, consistently
- 0.2pp/week floor: prevents threshold being trivially small for very stable brands
- 0.5pp/week ceiling: ensures high-volatility brands get alerted before it is too late

**Historical calibration at onboarding:**
At onboarding, apply Theil-Sen retrospective analysis to all available
complete BAU weeks. Identify historical periods where a known business
response occurred (spend pullback, discount depth increase, supplier change).
Find the Theil-Sen slope that preceded those responses.
Store as `trigger_b_theil_sen_multiplier` in client_config (default 0.20).
Outcome-tracked continuously. Default applies only when historical
calibration is insufficient.

**Urgency tier:** INFORMATIONAL (🟡) — trajectory signal, not acute crisis.

**Activation lag:** May take 3–6 months for event-heavy brands to accumulate
8 complete BAU weeks. This is acceptable and honest. Surface activation
lag as an insight in the Profit Audit, not as a product limitation.
