from Phase 1 connectors is dropped from Phase 1 entirely.

### Action-First Principle (2026-05-23)
Every alert must have: specific action + same-day execution +
diagnosable cause from available data. If any fail → Phase 2 or drop.

### No Margin Figure Without Reliable COGS (2026-05-26 Gap 1)

is Tier 1 (Finaloop) or Tier 1.5 (Founder CSV — fully reconciled).
For Tier 2/3 brands, D1 fires as a cost pressure alert naming
drivers only. No margin figure stated.

### No Hardcoding Principle (2026-05-26 Gap 2)
Every threshold, window, and comparison must be derived from the
brand's own data. Fixed pp values, fixed windows, and fixed
percentages are architectural debt.

### PRINCIPLE 3 — No Additivity. Directed Contribution — LOCKED

#### CM Impact Conversion Formulas (structure locked here,
#### display logic locked in Gap 9)

**Isolation principle:** each formula holds all other variables
at BAU level to isolate that driver's contribution.

| Driver | CM impact formula | Key assumption |
|--------|------------------|----------------|
| CPM rise | `(effective_cpa_this_week − effective_cpa_bau) × orders_this_week` | CVR held at BAU to isolate CPM. CVR decline is a separate driver. |
| Return rate rise | `(return_rate_this_week − return_rate_bau) × orders_this_week × avg_net_refund_value` | avg_net_refund_value from actual Loop/Shopify refund amounts — not AOV. Accounts for partial refunds. |
| Discount depth rise | `(discount_depth_this_week − discount_depth_bau) × gross_revenue_this_week` | Direct revenue reduction. |
| Fulfilment cost rise | `(fulfillment_cost_per_order_this_week − fulfillment_cost_per_order_bau) × orders_this_week` | Estimated from carrier data. Estimation flag applies (Principle 2). |
| SKU mix shift | `(margin_weighted_revenue_bau_pct − margin_weighted_revenue_this_week_pct) × gross_revenue_this_week` | Tier 1/1.5 only. Requires sku_cost_master. |

**effective_cpa denominator:** Shopify orders (not Meta-attributed
conversions) — avoids Meta attribution window discrepancy.
Limitation disclosed: "CPA calculated on total orders —
paid channel CPA impact may be higher."

#### Three-Layer Output Structure

**Layer 0 — Interaction check (fires first if triggered):**

Three hardcoded patterns:
1. Creative fatigue: CPM rising + CVR declining + return rate
   rising simultaneously
   → "These signals move together when paid creative is fatiguing.
      Check ad frequency and CTR decay before treating these as
      separate problems."

2. Collection launch echo: return rate rising + discount depth
   rising within 14–21 days of brand_event_calendar launch entry
   → "Return rate and discount depth are both elevated — pattern
      consistent with post-launch echo. Check whether launch-driven
      orders are returning at higher rates before adjusting
      discount strategy."

3. Platform cost shock: CPM rising across ≥2 channels
   simultaneously (Meta + TikTok, or Meta + Google)
   → "CPM is rising across multiple channels simultaneously —
      more consistent with a platform-wide cost event than a
      brand-specific creative problem. Check industry CPM
      benchmarks before making campaign changes."

AI-discovered interaction patterns:
- Multivariate sweep added to historical_pattern_scan.py
  (separate code path from bivariate sweep — do not merge)
- Stored in candidate_signals with:
  pattern_type = 'interaction'
  driver_combination = text[] of mart column names
  source = 'historical_scan'
  promotion_status = 'candidate'
- Promotion path: ≥5 historical instances at ≥70% hit rate
  → practitioner review (MANDATORY gate — not optional)
  → practitioner_approved = true
  → absorbs into live pattern library for this brand
- Cross-network: same combination across ≥3 brands of same
  vertical_tag → hardcoded into global interaction library
- calendar_clustered = true patterns: reviewed first at
  practitioner review, not blocked, but flagged prominently
- Causal graph lookup as fallback: if ≥2 drivers move together
  but no pattern matches → no Layer 0 fires. Safer than
  spurious interaction warning.

**Layer 1 — Driver list:**

  (current 24–48 hour read vs alert-week data)

**Layer 2 — Residual disclosure:**

#### Blind Spot Diagnostic (replaces Outcome B entirely)

Runs when residual > 70%. Five-step structured check.
Target: <10% of all cases reach Step 5.

```
Step 1 — COGS check:
  cogs_tier_active = Tier 2/3
  → "Most likely cause: a cost change we can't see.
     Check purchase orders and supplier invoices
     for changes in the last 14 days."
  Tier 1/1.5 → continue to Step 2.

Step 2 — SKU mix check (Tier 1/1.5 only):
  margin_weighted_revenue shifted vs BAU
  → surface as driver even if below normal threshold.
  Not applicable / no shift → continue to Step 3.

Step 3 — Fulfilment cost check:
  fulfillment_cost_per_order_this_week > bau × 1.15
  → flag as possible contributor with estimation disclosure.
  Not elevated → continue to Step 4.

Step 4 — Data integrity check:
  Any source sync gap > acceptable threshold in alert week
  → flag as potential false positive.
    Log internally. No founder-facing margin claim.
  All sources clean → continue to Step 5.

Step 5 — Genuine structural unknown (target <10% of cases):
  All four checks negative.
  → "We can see your margin compressed this week but the
     driver isn't visible in your connected data.
     The most likely cause is a cost change in your supply
     chain or fulfilment not yet captured.
     Review your [specific unlocked connector: Finaloop /
     3PL invoices / payment processor reports]
     for changes this week."
```

#### Change 1 — Adaptive Threshold (ceiling removed)

```
margin_mix_shift_threshold =
    MAX(bau_margin_weighted_revenue_sd × 1.5, 1.5pp floor)
```

- Ceiling removed entirely. High-volatility brands get a
  threshold that reflects their actual operating range.
- Floor retained at 1.5pp — prevents trivially small threshold
  for very stable catalogues.
- Rationale: Trigger A handles CM-level detection regardless.
  SKU mix threshold only needs to correctly identify when
  mix shift is a contributing driver.

#### Change 2 — Revenue Coverage Floor (not SKU count)

```
sku_cost_coverage_by_revenue =
```

  week's revenue — SKU mix impact unavailable."
- Additional check: if the single largest revenue SKU this week
  is missing a unit_cost → flag explicitly regardless of
  overall revenue coverage rate.

#### Tier 1/1.5 SKU Mix Shift — RETAINED

Formula:
```
margin_weighted_revenue_this_week =
    SUM(orders × sku_price × sku_margin_pct) /
    SUM(orders × sku_price)

margin_weighted_revenue_bau = same on BAU baseline orders

IF margin_weighted_revenue_this_week <
   margin_weighted_revenue_bau − margin_mix_shift_threshold
→ SKU mix shift is a contributing driver
```

Suppression conditions (ALL must be clear to fire):
1. No active event in brand_event_calendar (including echo)
2. No active promotion on shifted category
   (blended_discount_depth for that category not elevated vs BAU)
3. Revenue share shift exceeds adaptive threshold
4. Category proxy available (see below)
5. Not suppressed by seasonality check (Gap 6 dependency)

Output level: category, not SKU. Founder thinks in categories
and collections, not individual SKU numbers.

#### Category Proxy — Revised Priority Order

**Primary:** Shopify Collections (founder-created, brand-native)
- Assignment rule: primary collection = collection with fewest
  total SKUs that this SKU belongs to (most specific collection)
- Requires ≥70% of active SKUs to have collection membership

**Fallback:** AI inference + mandatory founder rename
- Claude API inference from: product title, tags, product_type,
  vendor, collection membership
- Mandatory founder rename step in onboarding:
  "We've grouped your products into categories —
   do these names match how you think about your business?
   Rename any that don't."
- Founder's renamed labels stored as ai_inferred_category
- Inference confidence must be ≥ 0.70 per SKU to use
- Below 0.70: fall back to product_type for internal grouping
  but never display product_type as a label

**Graceful skip:** collections < 70% populated AND founder
declines rename step → no category-level analysis for this brand.
Existing drivers still fire. No silent degradation.

**product_type:** retired as primary proxy. Retained as one
input signal to AI inference step only.
