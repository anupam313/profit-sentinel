### Q2 — Confidence Scoring Formula (LOCKED this session)

| Decision | Resolution |
|----------|-----------|
| Hit definition | Leading signal AND outcome both cross live-agent thresholds within lag ± 2 days |
| Hit rate type | Binary — 1 or 0 per instance, no magnitude weighting |
| Denominator | `observable_instance_count` only — instances where outcome window fully closed (trigger_date ≤ scan_date − (lag_days + 2)) |
| `instance_count` | All instances found including recent unobservable — written separately |
| Threshold at scan time | Recorded in `causal_pattern_validation.threshold_at_scan_time` (jsonb) for auditability |
| Tier boundaries — candidate | <4 observable instances OR <70% hit rate |
| Tier boundaries — provisional | 4–9 observable instances AND ≥70% hit rate (dead zone 6–9 closed) |
| Tier boundaries — core | ≥10 observable instances AND ≥80% hit rate |
| Boundary inclusivity | ≥70% and ≥80% are inclusive |
| Multi-signal gate — candidate/provisional | Active — corroborating signal required before alert fires |
| Multi-signal gate — core | Removed — fires on leading signal alone, same day threshold crossed |
| Novel chains at core tier | Gate retained until `practitioner_approved = true` manually set |

**Alert tone by tier:**
- `candidate`: hedged — "limited confidence", uncertainty disclosure, "we're watching for corroboration"
- `provisional`: standard Evidence Stack, specific recommendation, no uncertainty language
- `core`: assertive — "act now", instance count as explicit evidence, fires immediately
